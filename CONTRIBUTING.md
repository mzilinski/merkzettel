# Contributing to Merkzettel

Thanks for helping! Merkzettel is a small project; issues and pull requests
are welcome. Please read the [Code of Conduct](CODE_OF_CONDUCT.md) first.

## Ground rules

- Code, comments, commit messages and documentation are written in **English**.
  The website and the how-tos are bilingual (German default, English).
- Every user-visible string in C++ or QML goes through `i18n()`/`i18np()`/
  `i18nc()`. Never concatenate translated fragments.
- The German translation addresses the user with **du** (see DECISIONS.md D5).
- Keep commits small and focused; explain the *why* in the message body.
- New files need an SPDX header or must be covered by `REUSE.toml`;
  `reuse lint` must pass.

## Building and testing

```bash
cmake -B build -S . -DCMAKE_BUILD_TYPE=Debug -DMERKZETTEL_CLIENT_ID=<your-id>
cmake --build build -j
QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure
./build/bin/merkzettel --demo        # no account needed
```

Without a client ID the app builds and the demo works; see
[docs: Azure setup](https://mzilinski.github.io/merkzettel/docs/en/azure-setup/)
to register your own app for real sign-in.

Useful extras:

- `make screenshots`, `make videos`, `make docs`, `make site` — see the
  [developer guide](https://mzilinski.github.io/merkzettel/docs/en/developer/).
- `pre-commit install` enables the hooks (clang-format, REUSE, version
  consistency, whitespace).
- `-DMERKZETTEL_SANITIZERS=ON` builds with AddressSanitizer and UBSan.

## Pull requests

1. Fork and create a topic branch.
2. Make sure the build, `ctest`, `reuse lint` and `pre-commit run --all-files`
   pass.
3. Add a line to `CHANGELOG.md` under **[Unreleased]** for user-visible
   changes.
4. If you add UI strings, add the German translation to `po/de/merkzettel.po`
   (or leave it to the translators — CI reports missing ones).
5. Open the pull request using the template.

## Translations

The template `po/merkzettel.pot` is regenerated by `make pot`. To add a
language, copy it to `po/<lang>/merkzettel.po` and translate; the build picks
it up automatically. Details: [translation guide](https://mzilinski.github.io/merkzettel/docs/en/translating/).

## Releases (maintainers)

```bash
python3 scripts/release.py 0.5.0   # moves [Unreleased] in CHANGELOG, bumps CMake + metainfo
git commit -am "Release 0.5.0"
git tag -s v0.5.0 -m "Merkzettel 0.5.0"
git push --follow-tags
```

The release workflow builds the source tarball and Flatpak bundle and
publishes a GitHub release with the changelog excerpt.
