# Roadmap to release

Goal: Merkzettel installable in one step from Flathub and the AUR, stable in
daily use, fully documented, with a public website.

Legend: **[AUTO]** can be done by the maintainer tooling/agent,
**[HUMAN]** needs a person (accounts, legal, signing). Priority **P0** =
blocks release, **P1** = expected for release, **P2** = nice to have.
`[x]` done, `[ ]` open. Decisions are logged in [DECISIONS.md](DECISIONS.md),
progress summaries in [REPORT.md](REPORT.md).

## Phase 1 — Product

### Correctness and robustness

- [x] P0 [AUTO] Page through `@odata.nextLink` when fetching tasks and lists
  (today lists with more than 200 tasks are truncated and the cache drops
  the rest)
- [x] P0 [AUTO] Offline start: treat a stored refresh token as signed in,
  show cached data, retry the token refresh when the network returns
- [x] P0 [AUTO] Token refresh failures: `invalid_grant` / revoked consent
  signs out cleanly with an explanation; requests waiting on a refresh
  fail instead of hanging
- [x] P1 [AUTO] Fix self-referencing delta handler (leaks one closure per
  sync)
- [x] P0 [AUTO] HTTP 429/503: request queue (max 4 concurrent), Retry-After,
  bounded retries
- [x] P1 [AUTO] Network loss feedback: offline indicator, mutations while
  offline report a clear error instead of raw HTTP text
- [ ] P1 [AUTO] Conflicts: define last-writer-wins behaviour for edits of a
  task changed remotely, document it
- [ ] P1 [AUTO] Large lists (> 1000 tasks): verify model/cache performance
  with a generated data set
- [ ] P2 [AUTO] Startup time measurement and budget

### Packaging and identity

- [x] P0 [AUTO] App ID `io.github.mzilinski.merkzettel` (desktop file,
  metainfo, icons, Flatpak, D-Bus, KAboutData) with data migration
- [x] P0 [AUTO] Complete AppStream metainfo (screenshots with captions,
  releases, content rating, branding colours, URLs);
  `appstreamcli validate --strict` and `desktop-file-validate` clean
- [x] P0 [AUTO] Flatpak manifest against `org.kde.Platform` 6.x, minimal
  permissions, verified with `flatpak-builder`
- [ ] P0 [AUTO] AUR `PKGBUILD` for `merkzettel` and `merkzettel-git`, `namcap`
  clean
- [x] P0 [AUTO] Version in one place (CMake), `CHANGELOG.md` (Keep a
  Changelog)
- [x] P1 [AUTO] Login page explains permissions and offers the demo mode;
  builds without a client ID explain why sign-in is unavailable

### Quality gates

- [x] P0 [AUTO] QtTest suite: Graph client (mocked HTTP), add-bar date

- [ ] P1 [AUTO] QML smoke tests of the core flows in `--demo`, headless
- [x] P1 [AUTO] Static analysis: clang-tidy, clazy, cppcheck in CI

- [x] P1 [AUTO] ASan/UBSan test run in CI
- [x] P0 [AUTO] CI: Arch, Fedora, openSUSE, Ubuntu 26.04 LTS, Flatpak,

- [x] P0 [AUTO] Release workflow: tag → build → Flatpak bundle + source

- [x] P1 [AUTO] Pre-commit hooks (clang-format, reuse), `.clang-format`
- [x] P1 [AUTO] `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`,
  issue/PR templates
- [x] P1 [AUTO] REUSE compliance for every file

### Translation and accessibility

- [x] P0 [AUTO] German translation complete and consistent ("du"), `.pot`
  generated by the build, Weblate-ready layout
- [ ] P1 [AUTO] Accessible names on all icon-only controls, full keyboard
  operation, contrast check in Breeze Light/Dark

### Security

- [ ] P1 [AUTO] Review OAuth loopback redirect (port, state, PKCE), never
  log tokens, validate attachment file names/paths, dependency audit

### Features from the v0.3 roadmap

- [x] Delta sync (`@odata.deltaLink`)
- [x] Reminder notifications (KNotifications)
- [x] Subtasks (`checklistItems`)
- [x] Global quick-add shortcut (KGlobalAccel)
- [ ] P2 [AUTO] Multiple accounts — possible with the existing scopes, but
